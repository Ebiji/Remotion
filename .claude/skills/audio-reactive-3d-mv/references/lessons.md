# ユーザーの言葉から学んだこと(繰り返さない)

## 好まれたこと
- 「これはいいね」「素晴らしい」: **v1の画面の青み**、明るく鮮やかな色、曲がる道(v6)、ペイズリーの雲、曼荼羅が曲に合ってゆがむ。
- 「リズムと女性声のスキャットに合わせてほしい」: 打楽器だけでなく、**声**に反応させる。
- 題名は、**この例の書体**(Cormorant Garamond)、おしゃれで読みやすい。「Flowers & Towers」を縦三段組、最後の15秒。
- 「すごいよこれ!」: 4K描き→1080p/720pに縮めた版の、くっきりした画質。

## 直した/避けること
| 指摘 | 対応 |
|---|---|
| 中央の円がうるさい/小さい | 空いっぱいに広げて、バランスよく。曼荼羅は2小節だけ続ける |
| 画面が暗くなった | 明るく、鮮やかに(ただし白飛び・パステル化は避ける) |
| 視点を変えない | カメラは前方固定。道に沿って向きだけ |
| 縦揺れ・画面がちゃがちゃ | 揺れを2/3→さらに抑える。進む速さを半分に。**酔わないこと** |
| 円錐だけの木 | 詳細な植物(7種×LOD)。葉脈・樹皮・花弁 |
| 「MOUTH」の文字 | 入れない。文字は、依頼された題名だけ |
| v1の花の形が違う/道が曲がっていない | v1は **IFS花弁 + 直線道路**。v6の構成に引きずられない(`IS_V1`) |
| v1で音が入っていない | 音が入っているか、`volumedetect` で確認して伝える |
| 最後の音がフェードアウトしている | 私が足した `afade` が原因。**音は曲の自然な終わりまで**。+3秒の黒 |
| 画質が粗い | 原因は、(a)ビットレート不足 (b)1080p直描き(ギザギザ) (c)劣化したファイルからの再エンコード。**対策: 4K描き→縮小、元のチャンクから、`std`、必要ならビットレートを上げる** |

## 私のミス(防ぐ)
- 劣化したファイルを元に、さらに再エンコードして画質を落とした → **常に元のチャンクから**。
- 1コマ目(キーフレーム)だけで画質を判断した → **途中のコマ**を等倍で見る。
- 完了待ちコマンドが別プロセスを見ていて、早く「完了」と誤報した → ログとファイルの実体で確認。
- 4Kの題名を縮小せずに重ねてしまった → `finish_video.mjs` は、縮小時に題名も縮める(修正済み)。
- `git add -A` で動画やチャンクを誤ってコミット → `.gitignore` を整備、`001/out` を外す。
- 色の変換方式を明記せず、色がずれた可能性 → `std` で bt709 に変換して明記。
- **音は聴けない**。「確認できた」と言えるのは、数値(`volumedetect`)と静止画まで。
- 勝手に長時間・大容量の作業を始めない(始める場合は、見込み時間を先に伝える)。ユーザーが「止めて」と言ったら、**直ちに止める**。
- 無断で外部に出さない(PR・投稿など)。依頼のあったものだけ。
